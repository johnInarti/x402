Added the `delivery-receipt` extension (`@x402/extensions/delivery-receipt`, draft v0.2.1): a resource server signs, after a successful settle, a receipt binding the settlement (network, transaction, log index, asset, payTo, amount, payer) to the content it served — the SHA-256 of the response body, or for SSE routes the frame count and running digest of the frames sent, delivered in a terminal `x402-delivery-receipt` event. By default `PAYMENT-RESPONSE` carries only a reference `{ receiptId, receiptUrl, digest }` (within a 1 KB budget) and the receipt is served immutable at `receiptUrl` (`createMemoryReceiptStore` for tests); `receiptTransport: "inline"` is opt-in. Every receipt carries an `ed25519` signature for in-session verification (WebCrypto where available) and an `ml-dsa-65` signature over the same message for archival verification, and names the key-directory epoch and digest it was signed under; directories are served at a stable URL with per-epoch archives and a hash chain. Includes `withDeliveryReceipts` and `verifySseDelivery` for clients, and checks agreement with an `offer-receipt` receipt in the same settle response.
